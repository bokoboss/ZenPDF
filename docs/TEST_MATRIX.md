# ZenPDF Regression Test Matrix

This matrix defines the minimum behavioral checks for modernization work. It is designed to protect both PDF correctness and the existing ZenPDF interaction model.

## Test fixtures

Use synthetic/non-confidential fixtures committed to or generated by the test suite.

| Fixture | Purpose |
|---|---|
| `pdf-single-page.pdf` | Simplest valid PDF |
| `pdf-multi-page.pdf` | Basic merge/reorder/extract |
| `pdf-landscape.pdf` | Mixed page orientation |
| `pdf-pre-rotated.pdf` | Preserve and compose source rotation |
| `pdf-mixed-sizes.pdf` | A4/Letter/custom-size handling |
| `image-jpeg.jpg` | JPEG → PDF |
| `image-png.png` | PNG → PDF |
| `pdf-encrypted.pdf` | Graceful unsupported/encrypted behavior |
| `pdf-corrupt.pdf` | Error/recovery behavior |
| generated 100-page PDF | Medium performance fixture |
| generated 500-page PDF | Large-document behavior |

## Core behavioral matrix

### Import and parsing

- [ ] PDF reports the correct page count.
- [ ] JPG imports as one page.
- [ ] PNG imports as one page.
- [ ] Mixed PDF/image import preserves file order.
- [ ] Unsupported input is rejected without corrupting workspace state.
- [ ] Corrupt PDF produces a recoverable per-file error.
- [ ] Encrypted/password PDF produces a clear, recoverable state.

### Quick merge

- [ ] Two PDFs merge in file-list order.
- [ ] Reordered files merge in the new order.
- [ ] PDF + JPEG + PNG merge successfully.
- [ ] Source page dimensions are preserved where expected.
- [ ] Output page count equals the expected total.

### Page editor

- [ ] Editor initializes pages in document/file order.
- [ ] Single-page drag changes output order correctly.
- [ ] Multi-selected pages move as a group.
- [ ] Shift-select selects a contiguous range.
- [ ] Rotate page changes output orientation/rotation correctly.
- [ ] Rotate selected pages applies to all selected pages.
- [ ] Delete page removes it from the output.
- [ ] Delete selected pages removes all selected pages.
- [ ] Extract selected pages creates only the selected output pages.
- [ ] Add-file-from-editor appends/imports pages predictably.

### Undo/redo

- [ ] Reorder can be undone/redone.
- [ ] Rotate can be undone/redone.
- [ ] Delete can be undone/redone.
- [ ] Group move can be undone/redone.
- [ ] A new edit after undo clears redo history.
- [ ] Selection never references deleted/nonexistent page IDs after history operations.

### Reset and lifecycle

- [ ] Reset clears all files/pages/output URLs.
- [ ] Reset while parsing a large PDF does not allow stale worker messages to repopulate state.
- [ ] Reset while merging does not surface a stale completed output.
- [ ] Repeated merge/download cycles do not leak unbounded Object URLs.
- [ ] Removing a file releases thumbnail resources associated with that file.
- [ ] Worker failure can be recovered without a full browser refresh.

## Output verification

UI success is not sufficient. Tests should parse generated output and assert:

- page count
- page order
- page dimensions when relevant
- rotation
- successful PDF reopening/parsing

For visually meaningful cases, render selected output pages and compare against deterministic references with a tolerance appropriate for PDF rasterization.

## UI regression checks

The existing visual design is protected by `docs/DESIGN_GUARDRAILS.md`.

Capture representative screenshots for:

- upload/landing state
- populated documents list
- page editor with no selection
- page editor with multi-selection
- save/download-ready state
- error state
- desktop width
- narrow/mobile width

Visual regression tests should flag unintended changes to layout, spacing, typography, palette, radii, shadows, or component hierarchy.

## Accessibility and interaction checks

- [ ] All essential actions are keyboard reachable.
- [ ] Visible focus is present for keyboard interaction.
- [ ] Drag/reorder has a keyboard path.
- [ ] Page actions do not depend exclusively on hover.
- [ ] Touch interaction can select, rotate, delete, and reorder pages.
- [ ] Disabled/busy actions expose meaningful state.

## Performance acceptance targets

Exact thresholds should be established after measuring the current baseline on a representative machine. At minimum:

- The main UI thread should remain interactive during parsing/rendering.
- Large-document thumbnail work must be cancellable by session/reset.
- Visible pages should receive thumbnail priority over distant pages.
- Opening a large document must not require rendering every page thumbnail before the editor becomes usable.
