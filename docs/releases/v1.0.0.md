# ZenPDF v1.0.0

ZenPDF v1.0.0 closes the modernization of the browser-local PDF workspace while preserving the product's established calm visual design.

## Highlights

### Local PDF architecture

- PDF parsing and thumbnails run through a typed Vite module worker using `pdfjs-dist@6.2.108`.
- Merge, extract, rotation, and output generation use `pdf-lib@1.17.1`.
- PDF/UI dependencies are bundled locally; no runtime PDF-library or UI/font CDN is required by the tested application shell.
- Current document workflows remain browser-local and require no API key.

### Worker lifecycle and resource safety

- session/task-scoped typed protocol
- stale-response rejection
- cancellation, dispose, reset, and worker-restart behavior
- explicit browser Object URL ownership/revocation
- recoverable typed PDF errors

### Large-document scalability

- thumbnail updates are isolated from editor-wide page-order churn
- full logical page order is preserved
- expensive sortable/card/thumbnail subtrees are mounted only for visible/near-visible rows
- worker-wide thumbnail concurrency is capped at two
- visible/overscan source pages receive scheduling priority
- 100-page, 500-page, vector/text-heavy, and raster/scanned-like fixtures are release-qualified

Reference hosted v1 candidate:
- blank 500: 637 ms editor shell / 733 ms editor ready / 25 expensive sortables
- vector 120: 502 ms far-priority first thumbnail
- raster 100: 147 ms far-priority first thumbnail
- concurrency 2/2; duplicate successful renders 0

### PDF correctness

The regression suite covers page order/count, source dimensions, rotation composition, image/PDF workflows, extraction, malformed-file recovery, output provenance, undo/redo, mouse/keyboard/touch DnD, and downloaded-PDF reparse.

A v1 release blocker involving selection immediately after mouse DnD was reproduced deterministically and fixed before release. The protected Alpha/Beta output sequence is `400, 200, 420`.

### UX and accessibility

- keyboard-operable upload and navigation controls
- explicit accessible names and focus-visible treatment
- output position plus source provenance
- selected-count status
- failed-file inline state
- polite/alert toast semantics
- modal focus trapping/Escape/restoration
- logical focus after per-page deletion
- narrow touch qualification at 390×844 and 360×800

## Qualified release scope

Chromium is the automated/release-qualified browser baseline for v1.0.

Supported inputs:
- PDF
- JPG / JPEG
- PNG

## Known limitations

- Firefox/WebKit are not fully release-qualified.
- Prolonged edge-triggered mouse-drag auto-scroll remains nondeterministic in automated qualification.
- Large raster PDFs may spend substantial time in PDF parsing before thumbnail priority can help.
- Thumbnail reprioritization bounds stale in-flight work rather than cancelling every ordinary render.
- Malformed-file recovery is remove/re-add; there is no direct Retry action.
- No persistent workspace/session restore.
- No custom output filename editor.
- No shortcut-help UI or complex touch range-selection mode.
- 1,000-page stress remains targeted/manual.
- WebP/GIF/TIFF, Office conversion, OCR, and password-entry/decryption workflows are outside v1.0 scope.
